# Amazon purchase QA — 19 October 2026

Five cases passed on the current runtime-localization purchase-test APK: an existing account without active access, canceled checkout, expired subscription denial, lifetime account restoration and lifetime restoration after process restart. APK/source hashes and signed-status assertions are recorded in the device evidence. The original App Tester account, subscription settings, shared catalog and sandbox routing were restored; the ordinary app's data hashes remained unchanged. This is partial sandbox coverage, not production approval.

The isolated `com.dishnest.app.purchasetest` debug package exercises the actual Amazon SDK, installed App Tester and deployed Workers Free sandbox verifier. It has separate app storage. No ordinary DishNest installation was replaced, cleared or launched. App Tester orders are simulated; no customer payment or production purchase was made. These sandbox runs preceded the separately authorized private LAT submission; current LAT status is in `AMAZON_LAT.md`. No public release occurred.

## Observed results

`artifacts/amazon-purchase-device.json` binds current cases to APK/source hashes and retains earlier runs separately as historical evidence. The first lifetime order completed in App Tester, its real sandbox receipt was verified by Amazon RVS and the Worker, and the Android client granted Premium. The current APK subsequently passed lifetime restoration after returning to its account and after process restart. An existing account without active access, canceled-checkout denial and rejection of expired subscription claims also passed. A genuinely new customer still requires LAT coverage.

Both monthly and annual simulated subscription checkout screens completed. Their RVS responses supplied renewal dates approximately at the response time. Before the fix, a signed active claim could have only about 127 milliseconds of validity, which was already expired at the tablet. The Android verifier correctly rejected it. The same behavior occurred with App Tester auto-renew both off and on. We did not ignore expiry, invent a billing period, acknowledge delivery of unverified access or treat a completed checkout as an entitlement.

The receipt service now reads its decision clock **after** Amazon responds. A regression test proves a subscription expiring during the request produces a signed inactive decision instead of a stale grant. All 14 service tests pass, and updated Free-plan deployments return signed inactive decisions for these expired synthetic subscriptions while preserving the valid lifetime grant. See `artifacts/amazon-sandbox-receipt-review.json`. Real subscription renewal, cancel/refund, grace, restart/fulfilment, account and full LAT cases remain required.

One disposable purchase-test annual transaction was canceled in App Tester while retaining its history. The sandbox-only status activity then verified the current account's signed inactive cached fixture and sent one UNAVAILABLE fulfillment request. A new checkout subsequently opened and was canceled without granting access. It never sends FULFILLED for denied access. Cleanup is guarded by the exact debug package, sandbox endpoint, SDK SANDBOX mode, pinned signature, current account and inactive known SKU; cleanup reports cannot qualify as passing purchase cases. No other app's transactions were reset.

## Fire-specific test setup

This API-28 KFTRWI Fire defines `com.amazon.inapp.purchasing.Permission.NOTIFY` under `android.amazon.perm` with `signature|amazon` protection, but does not define the separate DRM notification permission. The system rejected App Tester's DRM broadcasts to the documented release receiver. The **purchase-test variant only** uses the existing protected Amazon IAP permission for that receiver. It never exposes an unprotected callback; the release receiver retains Amazon's documented DRM permission. This compatibility setup is not release/store validation.

Fire OS also blocked App Tester's background CommandBroker service. A 120-second temporary allowance, scoped only to App Tester, enabled each test batch. It was removed afterward. No permanent power whitelist or overlay permission was changed. Licensing starts from the activity lifecycle before purchasing registration, and its callback tolerates delivery before the request function returns. Diagnostic status, HTTP codes and stack locations are bounded and enabled only in the purchase-test package; they contain no accounts, receipts, secrets or request URLs. `PurchaseStatusActivity` exists only in that build variant, and the release APK validator checks its absence.

`tools/purchase_test_device.py` serializes device control with the existing Fire QA mutex, refuses a secure lock, matches observed UI controls and limits taps to the isolated app or App Tester. Its status probe returns to MainActivity using CLEAR_TOP so a diagnostic screen cannot hide account refresh. `tools/purchase_evidence.py` verifies the APK signature/identity, current Android source hashes, expected cases and complete restoration before packaging the test APK.

## Repeating safely

Read App Tester's current user/login and subscription auto-renew setting before setup. Pass those observed values to `setup --original-user 1 --original-login 'Logged In' --original-autorenew Off` (replace the values if different). The recovery file and original catalog live in the protected NTFS publisher folder outside Git. Do not clear App Tester or reset other apps' transaction histories.

Build only `assemblePurchaseTest` with `dishnest.billing.purchaseTest=true`, `dishnest.billing.environment=sandbox`, and the sandbox URL/public key from `artifacts/billing-deployment.json`. Ordinary `dishnest.billing.enabled` must remain false. Gradle rejects production/LAT endpoints and simultaneous ordinary billing enablement. Use the SDK controls to make simulated purchases; never tap a real Amazon checkout. `record` reads the sanitized status probe, and `confirm-settings` checks the original settings before `restore` restores the original shared catalog/routing and stops only the isolated package. Retained test receipts are private within that package and remain revocable.

The restoration report confirms the ordinary app's database, preferences and saved-file hashes are unchanged. It contains no hashes of individual personal records, account/receipt identifiers or device serial. The five current cases are partial purchase QA, not a certification of the remaining release categories. Secure signing-key recovery, exact publisher-signed hardware tests, native/legal approvals, final metadata and remaining scope decisions are still pending.
