# Seven remaining release gates

This is the handoff for the seven pending categories in `artifacts/submission-readiness.json`. A category stays pending until all of its required evidence exists. The user's conditional submission instruction does not waive these checks. No deployment is authorized.

## Run order

1. Finish chosen app changes and run the full host test/lint/build command recorded in `artifacts/delivery-verification.log`. Record fresh provenance using `tools/build_evidence.py`; source changes invalidate old binaries.
2. Validate locale coverage, listing/assets, native alignment and APK metadata. Run Fire smoke, then the separate background kitchen/timer probe sequentially. Both probes use only the disposable `com.dishnest.app.qa` package; ordinary kitchen data is outside their fixtures.
3. Record remaining hardware scenarios and actual native/publisher reviews. Configure billing/signing only with publisher-provided material, without storing secrets in Git or chat. Complete store forms from approved facts.
4. Regenerate readiness and deliverables. A strict preflight failure is an expected submission block while any category is pending. Do not replace pending statuses with approvals merely because a build or draft form is complete.
5. Commit and push reviewed local work. Submit the approved signed build to Amazon only after every required gate passes and the live console is reviewed. Keep all reports tied to the exact submitted artifact.
